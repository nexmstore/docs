## Return conventions

NEXM Core uses three return patterns consistently:

- **Getters** return `value, err`. On success, `value` is populated and `err` is `nil`. On failure, `value` is `nil` and `err` is an error object.
- **Mutations** return `ok, err`. On success, `ok` is `true`. On failure, `ok` is `false` and `err` describes what went wrong.
- **Predicates** return `boolean, err`. A `false` result means the condition is not met. An `err` object means the check itself failed (for example, invalid input or a missing player).

See the [error model](/reference/error-model) for the shape of `err` objects and how to handle them.
